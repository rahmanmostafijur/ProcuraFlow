and Vercel services do not exist, so pushing triggers nothing. Backend 242 tests, frontend 58 tests, type-check and

Read the README sections "Deployment", "Reverse proxy and client addresses", "Migrations and scaling",
"Post-deployment verification" and "Security notes" before acting on anything below.

## 1. Deploy (manual, needs your accounts)

1. **Neon.** Create the project. Copy both connection strings: the pooled (`-pooler`) one and the direct one.
2. **Render.** New > Blueprint from this repo (`render.yaml`). It asks for three secrets:
   `DATABASE_URL` (pooled string), `DEFAULT_ADMIN_EMAIL`, `DEFAULT_ADMIN_PASSWORD` (unique, 12+ characters).
   Also add `MIGRATION_DATABASE_URL` set to the **direct** Neon string. `JWT_SECRET_KEY` is generated by Render.
   `SEED_DEMO_DATA=true` and `TRUSTED_PROXY_HOPS=2` are preset; delete `SEED_DEMO_DATA` for a real deployment.
3. **`frontend/vercel.json`.** Replace `REPLACE-WITH-YOUR-RENDER-SERVICE` in the `/api` rewrite with the exact Render
   hostname, commit and push.
4. **Vercel.** Import the repo with Root Directory `frontend`. No environment variables.

## 2. Verify on real hosting (nothing below has been checked yet)

Work through the 13 items in README "Post-deployment verification". The ones that most need a real environment:

- **Proxy hop count.** `TRUSTED_PROXY_HOPS=2` assumes client -> Vercel -> Render with Render appending its peer.
  Fail one sign-in through the Vercel URL and read the Render log line
  `failed sign-in client_ip=<addr> forwarded_entries=<n>`. Expect your public address and `2`. If it shows `None`
  with another count, set the variable to that count. If it shows a Vercel or Render address, do not raise it.
- **Vercel rewrite and cookies.** The `refresh_token` cookie is `HttpOnly`, `Secure`, `SameSite=Lax`, path
  `/api/v1/auth`, on the Vercel domain, and rotates on reload.
- **Neon pooler.** Migrations use the direct URL; the app runs on the pooled one. Confirm sign-in and the dashboard work.
- **CSP on the real Vercel URL.** No `Content-Security-Policy` violations in the console. Vercel preview deployments
  inject a toolbar script that the policy blocks; production does not.
- **Throttle persistence.** After a lockout, restart the Render service; the account stays locked.
- **Cold start.** After 15+ minutes idle the login page shows the waking notice and never spins forever.

## 3. Known limits, decided not to fix (see README "Security notes" and "Future Improvements")

- Tailwind 3 build-chain advisories (dev only; fix is a Tailwind 4 rewrite).
- `pytest` 8.3.4 advisory (UNIX shared `/tmp` only; fix needs pytest 9 plus a pytest-asyncio major upgrade).
- Someone who reaches the Render URL directly can choose their own client address, affecting only the per-address
  throttle check. Closing it needs restricting direct access (a paid Render feature).
- An account can be kept locked for 15 minutes by someone who knows its email.
- An access token already issued stays valid for up to 30 minutes after logout or a password change.
- No linter is configured (no ruff, no ESLint); type-check and build are the static checks.
